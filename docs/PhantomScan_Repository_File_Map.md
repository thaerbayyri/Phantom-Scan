# Phantom Scan — Repository File Map (Phase 1 Audit)

**Scope:** every tracked file in the repository (`git ls-files`, 1,682 files), inventoried read-only.
No files were deleted, moved, renamed, or edited to produce this report.

**Method:** research was parallelized across 8 file-category agents plus direct investigation by
the orchestrating session for vendored/embedded trees and stray config files. Each agent read file
content for purpose, and checked static imports, build/CI config, doc cross-references, CLI/manual-
invocation signals, and git history before assigning a usage status.

## Excluded from this inventory

These directories exist on disk but are **not tracked by git** (confirmed via `git ls-files`) and
are excluded per the audit instructions — generated/vendor/cache output, not source:

| Path | Why excluded |
|---|---|
| `.git/` | VCS internals |
| `node_modules/` | npm-installed dependencies (regenerated by `npm install`) |
| `.venv/` | Python virtualenv (regenerated by `pip install`) |
| `dist/`, `build/` | Build output (regenerated by `npm run build`) |
| `.pytest_cache/` | pytest cache |
| `.benchmarks/` | pytest-benchmark cache |
| `.tmp/` | scratch/temp directory |
| `.claude/`, `.codex/`, `.agent/` | AI-tool local config/cache directories |
| `.docx_deps/` | vendored Python wheels for the docx report-builder scripts (cp313-only, per project memory) |
| `bash.exe.stackdump` | crash artifact from a shell crash, untracked |

Two further trees **are** tracked but are vendored/embedded dependency code, not this project's
own source — inventoried as single line items rather than file-by-file (see their own sections
below): `firmware/esp32-csi-node/managed_components/` (1,199 files) and
`ai model and densepose/model/` (a nested git repository/gitlink).

Reconciliation: 483 first-party tracked files + 1,199 vendored ESP-IDF component files = 1,682
tracked files total (matches `git ls-files | wc -l` exactly).
